# 数据模型说明

> 当前版本（v0.1.0）**没有后端**，所有数据通过微信本地缓存 `wx.setStorageSync` 读写。
> 本文件描述现有缓存结构，同时给出接入后端后的建议表结构。

---

## 一、本地缓存 Key 一览

| Key | 类型 | 写入位置 | 说明 |
| --- | --- | --- | --- |
| `userInfo` | Object | `pages/login/login.js` | 当前登录用户，认证通过时写入 |
| `orders` | Array | `pages/place/place.js`、`pages/orders/orders.js`、`pages/receive/receive.js` | 全部订单列表 |
| `conversations` | Array | `pages/login/login.js` 初始化 | 会话列表 |
| `messages` | Array | `pages/login/login.js` 初始化、`pages/chat/chat.js` | 聊天消息 |
| `token` | String | `app.js` | 登录凭证，接入后端后有效 |

初始化时机：登录页 `submitVerify()` 成功时会把 `orders`、`conversations`、`messages` 初始化为空数组。

## 二、User（用户）

```js
{
  id: 'u_1712345678901',          // 'u_' + Date.now()
  nickname: '张三',                // 昵称
  phone: '13800138000',           // 手机号
  studentId: '2024000001',        // 学号
  verified: true,                 // 是否已通过认证
  avatar: '张',                   // 昵称首字符（大写）作为头像占位
  joinDate: '2026-04-11T10:00:00.000Z',
  credit: 100,                    // 信用分，初始 100
  completedOrders: 0,             // 已完成订单数
  publishedOrders: 0              // 已发布订单数
}
```

字段说明：
- `avatar` 目前是文字头像（取昵称首字符），未存储真实头像 URL。
- `credit` / `completedOrders` / `publishedOrders` 已定义但**尚未参与业务逻辑**。

## 三、Order（订单）

```js
{
  id: 'order_1712345678901_a1b2c3',   // 'order_' + 时间戳 + 随机串
  creatorId: 'u_1712345678901',
  creatorNickname: '张三',
  creatorPhone: '13800138000',

  orderType: 'express',               // express | canteen | snack | other
  orderTypeText: '快递代拿',
  description: '中通快递，小件',

  pickupLocation: '乔相阁宿舍楼',       // 取件地点
  deliveryLocation: '风槐斋宿舍楼',     // 送达地点
  price: 3.5,                         // 赏金（元）

  waitMinutes: 30,                    // 等待接单时长（分钟）
  expectedDeliveryMinutes: 45,        // 期望送达时长（分钟）
  expectedDeliveryText: '45分钟',
  remark: '放门口即可',

  status: 'waiting',                  // waiting | accepted | completed | canceled
  createTime: '2026-04-11T10:00:00.000Z',
  expireTime: 1712347478901,          // Date.now() + waitMinutes * 60 * 1000

  takerId: null,                      // 接单者 ID
  takerNickname: null,
  takerPhone: null,
  takerAcceptTime: null,
  completeTime: null,

  privateInfo: {                      // 私密信息，仅接单后对双方可见
    pickupCode: '8-2-3301',           // 取件码
    roomNumber: 'A305',               // 门牌号
    contactPhone: '13800138000'       // 联系电话
  }
}
```

### 状态流转

```
waiting ──接单──> accepted ──完成──> completed
   │                  │
   └──取消──> canceled ──┘
```

- `waiting`：发布后初始状态，出现在接单大厅
- `accepted`：被接单，`takerId / takerNickname / takerAcceptTime` 被写入
- `completed`：接单方或发布方确认完成
- `canceled`：发布方取消

> 注意：`expireTime` 已计算，但**没有定时任务**把超时 `waiting` 订单置为 `canceled`。

## 四、Conversation（会话）

```js
{
  conversationId: 'conv_xxx',         // 会话唯一 ID
  participants: ['u_1', 'u_2'],       // 参与者 ID 数组
  orderId: 'order_1712345678901',     // 关联订单
  lastMsg: '好的，马上到',
  lastTime: '2026-04-11T10:05:00.000Z',
  unreadCount: 0
}
```

- 列表页按 `lastTime` 倒序排列，并展示未读数红点。
- 进入聊天页时调用 `markAsRead()` 将 `unreadCount` 归零。
- **当前接单流程不会自动创建会话**，需要在接单时补充 `conversations.push(...)` 逻辑。

---

## 五、Message（消息）

```js
{
  id: 'msg_1712345678901_0.123456',
  conversationId: 'conv_xxx',
  senderId: 'u_1',
  content: '我已经到快递柜了',
  timestamp: '2026-04-11T10:05:00.000Z'
}
```

- 发送时同步更新会话的 `lastMsg` 与 `lastTime`。
- 消息按 `timestamp` 升序渲染，`scrollTop` 置为最大值以滚动到底部。

## 六、接入后端后的建议表结构

若后续接入服务端，可参考以下设计（MySQL 示例）：

```sql
-- 用户表
CREATE TABLE user (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  openid        VARCHAR(64) UNIQUE NOT NULL,
  nickname      VARCHAR(64),
  phone         VARCHAR(20),
  student_id    VARCHAR(32),
  credit        INT DEFAULT 100,
  verified      TINYINT DEFAULT 0,
  created_at    DATETIME
);

-- 订单表
CREATE TABLE orders (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  creator_id    BIGINT NOT NULL,
  taker_id      BIGINT,
  order_type    VARCHAR(16),
  description   VARCHAR(255),
  pickup_loc    VARCHAR(128),
  delivery_loc  VARCHAR(128),
  price         DECIMAL(8,2),
  status        VARCHAR(16),
  expire_at     DATETIME,
  created_at    DATETIME
);

-- 会话表 / 消息表
CREATE TABLE conversation (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  order_id      BIGINT,
  user_a        BIGINT,
  user_b        BIGINT,
  last_msg      VARCHAR(255),
  last_time     DATETIME
);

CREATE TABLE message (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  conv_id       BIGINT,
  sender_id     BIGINT,
  content       TEXT,
  created_at    DATETIME
);
```

敏感字段（取件码、门牌号、联系电话）建议单独建表并加密存储，仅订单双方可见。
